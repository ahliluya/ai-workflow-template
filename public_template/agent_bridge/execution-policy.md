# Execution Policy / 执行策略

## Required sequence / 必须执行的顺序

1. Inspect before modifying. / 修改前先检查。
2. Confirm the goal, scope, allowed files, and stop conditions. / 确认目标、范围、允许文件和停止条件。
3. Make small, reversible changes. / 进行小型、可逆的修改。
4. Verify after modifying. / 修改后进行验证。
5. Report clearly with `result-template.md`. / 使用 `result-template.md` 清晰报告。
6. Review the diff and result before committing. / 提交前审查差异和结果。
7. Commit only after review and approval. / 仅在审查和批准后提交。
8. Create a backup after a stable milestone when the project requires one. / 项目需要时，仅在稳定里程碑后创建备份。

The User remains final approver. Execution policies do not grant permission for destructive, external, or paid actions. / 用户始终是最终批准者。执行策略不授权破坏性、外部或付费操作。
